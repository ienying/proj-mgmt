# Dock 栏工单提交 — 系统提示词

> 本文档根据现有代码实现反向梳理，可作为在其他项目中复刻该功能的提示词。

---

# 角色
你是一个全栈开发专家，精通 Next.js + React + TypeScript + PostgreSQL 技术栈，同时具备企业工单系统的架构设计能力。

# 任务
在 Dock 栏工单提交模块新增外部人员扫码提报工单功能，区别于内部用户提报流程。

---

## 一、模块定位

工单模块位于 Dock 导航栏，包含两套提交流程：

1. **内部用户提报**：完整表单，含人员/时间/告知对象/信息分类等内部字段（已有功能，本需求不涉及）
2. **外部人员扫码提交**：简化表单，仅需核心信息，统一流转至指定处理人（本次新增）

---

## 二、外部扫码提交表单

### 2.1 表单字段

仅需填写以下字段，无需内部工单字段（人员/时间/告知对象/信息分类等）：

| 字段 | 必填 | 类型 | 说明 |
|------|:--:|------|------|
| 客户名称/所属项目 | * | 文本 | 关联已有项目或手动输入 |
| 客户姓名 | * | 文本 | 外部联系人姓名 |
| 职务 | | 文本 | 对外职务 |
| 联系方式 | * | 文本 | 手机号码或邮箱 |
| 问题描述 | * | 多行文本 | 完整详细的问题描述 |
| 辅助举证附件 | | 文件上传 | 支持视频/图片/文档 |

### 2.2 附件存储

上传的视频/图片/文档**不存数据库**，而是存储到服务器指定目录：

```
./data/work-order-attachments/{工单ID}/
```

数据库中仅记录文件路径指针，不存 base64 或 blob。

### 2.3 扫码入口

- 生成唯一的扫码 URL，携带工单来源标识
- 外部用户扫码后直接进入简化提交页面，无需登录系统
- 页面为独立公开路由（如 `/work-order/external?token=xxx`）

---

## 三、工单流转规则

### 3.1 指定接收人配置

在系统设置 → 工单配置中，管理员可指定外部工单的接收用户：

- 支持指定**多名用户**作为外部工单处理人
- 所有外部扫码提交的工单统一写入这些用户的待办事项
- **一人处理即完成**：当其中任意一位处理人处理了该工单后，其他处理人的待办列表中该工单自动移除

### 3.2 待办集成

- 外部工单创建后，自动生成待办任务实例
- `source_type = 'work_order_external'`
- 分配给所有指定的接收用户
- 任一用户处理后，其余用户的该待办标记为已处理（closed/cancelled）

---

## 四、数据库设计

### 4.1 工单表

在现有工单表基础上新增字段标识来源：

| 新增字段 | 类型 | 说明 |
|----------|------|------|
| source | text | `internal` / `external` |
| external_token | text | 外部访问 token（唯一） |
| external_customer_name | text | 客户名称 |
| external_contact_name | text | 客户姓名 |
| external_contact_title | text | 职务 |
| external_contact_info | text | 联系方式 |

### 4.2 工单配置表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid PK | |
| config_key | text | `external_order_assignees` |
| config_value | jsonb | `{ "user_ids": ["uuid1", "uuid2"] }` |

### 4.3 附件路径规则

附件文件存储到 `./data/work-order-attachments/{工单ID}/`，数据库中存相对路径：

```json
["{工单ID}/video_001.mp4", "{工单ID}/image_001.png"]
```

---

## 五、API 设计

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/work-order/external-config` | 获取外部提交配置 |
| POST | `/api/work-order/external` | 外部用户创建工单（无需登录） |
| POST | `/api/work-order/upload` | 上传附件到服务器目录 |
| GET | `/api/work-order/external-attachments/:id` | 获取工单附件下载链接 |

---

## 六、安全设计

- 外部提交接口需 token 校验，防止恶意提交
- Token 有效期可配置（默认 7 天）
- 同一 token 可多次提交（允许多个问题）
- 附件大小限制：视频 ≤ 200MB，图片 ≤ 10MB，文档 ≤ 50MB
- 提交频率限制：同一 IP 每分钟最多 3 次提交

### 7.4 必填标记

- 标签旁红色 `*` 星号
- 提交时校验，未填项边框变红 + 下方红色提示文字

### 7.5 交互动效

| 元素 | 动效 | 时长 |
|------|------|------|
| 页面进入 | fadeIn + translateY(10px→0) | 300ms |
| 输入框聚焦 | border 变色 + ring 展开 | 200ms |
| 提交按钮 | hover 加深 / active 按压 | 100ms |
| 已选文件删除 | fadeOut + 右滑 | 200ms |
| 成功图标 | scale(0→1) bounce | 500ms |

### 7.6 响应式

- 最大宽度 480px 居中
- 小屏 (<360px)：padding 减至 16px，字号 14px
- 附件区堆叠

### 7.7 通用规则

- 外部提交页面独立设计，无登录态和全局导航栏
- 表单字段间间距 20px
- 提交成功展示工单编号供后续追踪
- 附件大小限制：视频 ≤ 200MB，图片 ≤ 10MB，文档 ≤ 50MB

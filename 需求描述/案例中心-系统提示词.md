# 案例中心 — 系统提示词

> 本文档根据现有代码实现反向梳理，合并用户画像和产品案例两大功能模块，可作为在其他项目中复刻该功能的提示词。

---

# 角色
你是一个教育信息化客户画像结构化建模工程师，精通 Next.js + React + TypeScript + PostgreSQL，同时具备企业级 BI 数据看板设计能力。

# 任务
实现「案例中心」——包含用户画像（单客户深度画像）和产品案例（跨项目聚合）两大功能。面向学校客户，公司提供智慧校园整体解决方案，覆盖管理、教学、德育、安防、局端对接、物联网硬件等 101 个产品模块。

## 一、系统定位

案例中心是项目管理系统的**独立顶级模块**，在 Dock 导航栏上以独立图标呈现。

```
Dock 导航栏
  项目管理 │ 任务中心 │ 案例中心 │ ...
                        │
                  ┌─────┴─────┐
                用户画像    产品案例
                (单客户)    (跨项目聚合)
```

- **用户画像**：从客户科室出发，逐科调研业务 → 匹配适用模块 → 追踪落地效果
- **产品案例**：以模块为维度，跨学校聚合使用案例和素材

### 系统边界

| ✅ 允许 | ❌ 禁止 |
|--------|--------|
| 新建独立 Schema `design_case_center` 存放所有表 | 修改已有功能代码、表结构、业务逻辑 |
| 新增案例中心相关接口、页面、Dock菜单项 | 改动已有项目、客户、任务等数据表 |
| 读取项目基础数据自动同步 | — |

## 二、全局 UI 设计原则

### 2.1 视觉风格

案例中心整体风格定位为**数据看板（Dashboard）**，而非传统管理后台列表页。核心要求：

- 每个卡片/模块必须有**视觉权重**：用颜色（绿/蓝/黄/灰）、左边框色带、进度条、数字大字体区分重要程度
- 数据指标用**大号数字 + 小号标签**，卡片底色浅灰/浅色微区分
- 顶部核心指标卡使用**彩色图标 + 深色数字**，类似 BI 看板的 KPI 卡片
- 整体风格像看板一样炫酷，不同业务板块有不同颜色或装饰，但不能太花哨

### 2.2 配色方案

| 用途 | 颜色 | 色值 |
|------|------|------|
| 主色 | 靛蓝 indigo | `#4f46e5` |
| 成功/正式使用 | 绿色 | `#16a34a` |
| 试用/推广中 | 蓝色 | `#2563eb` |
| 已购未用/警告 | 黄色 | `#ca8a04` |
| 未购/禁用 | 灰色 | `#d1d5db` |
| 背景 | 浅灰 | `#f3f4f6` |
| 卡片 | 白色 | `#fff` |

### 2.3 布局规则

- 左侧深色固定 Dock 栏（80-100px），顶部面包屑栏（56px 固定），内容区滚动
- 卡片间距 16-20px，圆角 10px，轻微阴影
- 状态徽章统一使用圆角胶囊形状（pill badge）
- 模块卡片左边框 4px 色带区分状态（绿/蓝/黄/灰）
- 选择框无论选择与否宽度固定，保持排版对齐

### 2.4 交互规则

- 悬停：卡片上浮阴影加深、表格行变色、按钮微变色
- 进度条：高度 6-8px，圆角，填充分色

### 2.5 响应式

- 小屏幕侧边栏折叠为图标模式（60px）
- 统计卡片网格自动换行（最小 200px 每列）

## 三、用户画像

### 3.1 核心思路：科室 → 模块

画像从客户内部视角出发，不按产品线罗列模块，而是从学校各科室的实际业务入手：

```
科室走访 → 了解该科室日常做什么、怎么做的、痛在哪
       → 匹配哪些模块能解决这些痛点 / 已在使用哪些模块
       → 记录每个模块的真实使用情况
       → 画像 = 所有科室的汇总全景
```

### 3.2 多校区管理

支持三种校区管理模式：

| 模式 | 特征 | 处理方式 |
|------|------|---------|
| **单校区** | 只有一个校区 | 标准画像，不启用校区概念 |
| **多校区独立** | 各校区独立管理 | 每个校区一份完整的科室+模块数据 |
| **多校区交叉** | 部分部门全校统一，部分分校区 | 全校统一部门标「全校共享」，分校区的逐个填写 |

数据库字段：
- `campus_mode`：single / multi_independent / multi_cross
- `campuses` JSON 数组：`[{name, type, address, hardware:{...}}]`
- 科室字段：`dept_scope`（school_wide / campus_specific）、`campus_id`

### 3.3 科室与模块对照关系

一个模块通常由一个主要科室主导，同时需多个科室协同配合。

| 科室 | 主要使用模块 | 参与协同 |
|------|-------------|---------|
| **校领导** | 数据大屏/驾驶舱、流程审批、数据可视化 | — |
| **教务处** | 课表中心、考务管理、成绩管理、在线巡课、教学质量、基础教务 | 教研室、信息中心 |
| **教研室** | 集体备课、网络教研、资源中心、科研项目、知识库 | 教务处、信息中心 |
| **学生处/德育处** | 德育管理、班级评价、综合素质、特殊学生库、学生请假 | 宿管科、保卫处、心理中心、年级组 |
| **信息中心** | 基础数据中心、认证管理、数据开放、表单管理、第三方对接、流程管理 | **所有科室** |
| **人事处** | 人事管理、教师档案、教师考勤、薪资管理 | 教务处、财务处 |
| **财务处** | 网上收费、薪资管理、缴费管理 | 人事处、学生处 |
| **后勤/资产处** | 资产管理、耗材管理、空间预约、食堂管理 | 信息中心、教务处 |
| **保卫处** | 进出校管理、访客管理、视频融合、在线巡查 | 学生处、宿管科、年级组 |
| **招生办** | 招生管理、迎新报到 | 信息中心、财务处 |
| **就业处/实习办** | 实习管理、毕业去向 | 教务处、学生处 |
| **督导室** | 督导评估、教学督导、教师评价 | 教务处、教研室 |
| **心理中心** | 身心健康、特殊学生库 | 学生处、年级组 |
| **宿管科** | 宿舍管理、人脸面板机/宿舍牌 | 学生处、保卫处、年级组 |
| **校办** | OA办公、公文管理、会议管理、任务协同 | **所有科室** |
| **年级组/学院** | 班级主页、家校通知、学生档案、综合考勤、晨午检 | 学生处、教务处、宿管科 |

### 3.4 多科室协同模块处理规则

| 场景 | 处理方式 |
|------|---------|
| **录入时** | 模块归属到主要使用科室，在「协同科室」字段勾选其他参与科室 |
| **查看时** | 主科室完整展示，协同科室以「协同参与」标签简化展示 |
| **编辑时** | 修改模块状态，主科室和协同科室同步更新 |
| **统计时** | 模块只计入主要科室的计数 |

### 3.5 画像录入/编辑

三种更新路径：

| 路径 | 入口 | 适用场景 | 触发版本 |
|------|------|---------|---------|
| **新建画像** | 列表页「+ 新建画像」→ 空白表单 | 首次建档 | v1 |
| **直接编辑画像** | 详情页「编辑」按钮 → 预填充表单 | 定期更新（如季度回访） | v2, v3, v4... |
| **周报录入** | 详情页「本周周报」→ 周报表单 | 日常运维记录 | 每次提交生成版本 |

#### 3.5.1 新建/编辑表单布局

单页表单（类似新建项目页面），从上到下按科室走访顺序排列：

**基础信息**：
- 学校名称：下拉搜索选择，宽度固定。选择来源于新建项目的学校名称
- 学校类型（客户类型）：下拉多选——幼儿园、小学、初中、中职、高中、高职、技师、教育局。幼儿园/小学/初中/中职/高中支持多选，多选后考虑不同阶段画像
- 位置信息：直接同步项目管理创建项目的数据（省/自治区/直辖市、区/县、镇/乡、市、村、经度、纬度），项目管理更新则画像同步更新
- 硬件与网络信息：无线覆盖和堡垒机选项放在一起
- 描述：多行文本
- 学校照片：多图上传

**校区配置**（多校区模式时）：
- 校区列表配置面板：校区名称、学校类型、学校地址
- 每个校区的教学楼、宿舍、食堂等硬件独立填写

**科室业务表单**（每个科室一个折叠面板，按科室顺序排列）：
- 科室名称：除校领导外都支持修改（不同学校科室名称可能不同，但需考虑可对比性）
- 多校区交叉模式：先选「覆盖范围」→ 全校共享 or 校区专属
- 每个科室面板加背景颜色区分
- 字段：

```
科室负责人：姓名 | 职务 | 联系方式
日常核心工作：___
业务流程（他们怎么做的）：___
当前痛点：___
在用工具/系统：___
信息化期望：___
（以上全部为多行文本）

▼ 模块匹配
  [下拉搜索添加模块] ← 模块名称来源于系统设置→基础数据→产品名称→模块名称（显示前端中文名称）
  模块状态：
    🟢 正式使用 ｜ 🔵 试用/推广中 ｜ 🟡 已购未用 ｜ 🟠 未购(标注当前做法)
  使用率___%  |  活跃用户___  |  效果___  |  问题___
  协同科室（勾选）：□教务处 □学生处 □保卫处 □信息中心 □宿管科 □年级组 □校办 □...
  （所有文本输入字段为多行文本，选择项对齐）

  产品素材：🟢正式使用/🔵试用中的模块右侧「📎」按钮上传视频/PPT/文字
```

底部固定操作栏：「保存草稿」+「提交」。

#### 3.5.2 下载模板导入

新建画像时支持下载 Excel 模板导入数据。

### 3.6 画像查看（科室视角 UI）

#### 3.6.1 总览仪表盘

进入单个画像后，最左侧固定一个深色 Dock 栏（80-100px，类似 macOS Dock 竖放）：

```
┌─────┬──────────────────────────────────────────┐
│科室 │  XX学校 · 类型标签 · 校区模式 · 等级      │
│Dock │  更新日期            [编辑画像] [AI报告]   │
│     │──────────────────────────────────────────│
│ 🏫  │  已购:N  🟢正式:N  🔵试用:N  覆盖:N%     │
│校领导│                                          │
│ ●3/3│  校区切换：[全校▾] [本部高中] [初中部]...  │
│     │                                          │
│ 📋  │  ◆ 教务处（当前选中，Dock 高亮）           │
│教务处│  ┌──────────────────────────────────┐   │
│ ●5/6│  │ 科室人员 + 业务描述 + 模块列表      │   │
│─────│  │ (每个模块卡片：左边框色带+使用率    │   │
│ 👥  │  │  进度条+效果描述+素材入口)          │   │
│学生处│  └──────────────────────────────────┘   │
│ ◎3/5│                                          │
│ ... │  该科室总结：X模块中正式使用N个...         │
│(滚动)│                                          │
│─────│                                          │
│ 📜  │                                          │
│版本  │                                          │
│ 📝  │                                          │
│周报  │                                          │
└─────┴──────────────────────────────────────────┘
```

**Dock 栏设计要点**：
- 左侧深色固定（`#1e293b`），每个科室：emoji 图标(24px) + 简称(12px) + 状态圆点
- 落地状态圆点：🟢有正式使用 / 🟡仅有已购未用或试用 / ⚪全未购
- 当前选中科室高亮 + 左侧 3px 蓝色指示条
- 底部固定入口：「📜 版本」「📝 周报」
- 鼠标悬停弹出 Tooltip：「科室全名 · N模块落地/N模块匹配 · 负责人」

**右侧内容区**：
- 顶部：学校名称 + 类型标签 + 等级徽章
- 核心指标卡片栏（已购/正式使用/试用中/素材覆盖率）
- 校区切换胶囊按钮（仅多校区时显示）
- 当前科室完整详情

#### 3.6.2 模块卡片设计

- 🟢 正式使用 → 绿色左边框，展示使用率进度条 + 效果描述 + 素材入口 + [📎素材：N个文件] [查看详情]
- 🔵 试用/推广中 → 蓝色左边框，展示试用范围、推广进度
- 🟡 已购未用 → 黄色左边框，展示搁置原因
- 🟠 未购 → 灰色左边框，展示当前替代做法
- 过滤器：「只看使用中」/「全部」

#### 3.6.3 跨科室对比视图

勾选 2-4 个科室并排对比：匹配模块数、正式使用数/率、使用率均值、素材数、核心痛点、人员态度 + 结论总结。

#### 3.6.4 列表页

| 学校 | 类型 | 等级 | 科室数 | 已购模块 | 🟢正式 | 🔵试用 | 更新 |
- 点击学校名 → 进入总览仪表盘
- 搜索框 + 类型/等级/省份筛选
- 支持批量导出 Excel

### 3.7 周报录入

从画像详情页点击「本周周报」，以**全屏弹出面板**打开（占屏幕 2/3 宽度，右侧滑入动画 300ms）：

周报表单结构（单页滚动）：

| 板块 | 内容 | 字段类型 |
|------|------|----------|
| 诚信声明 | 确认记录真实 | 勾选框 |
| 每日工作 | 逐日记录工作内容（含培训/试点/案例拍摄） | 多行文本，按日分组 |
| 巡检维护 | 巡检时间/范围/隐患/是否上报处理 | 表单+下拉 |
| 应用落地宣传 | 宣传主题(模块)/图片视频/说明 | 文本+文件上传 |
| 了解客户业务 | 科室/人员/职务/核心业务/产品适配/效果反馈 | 下拉+文本 |
| 市场贡献 | 线索来源/内容/对接建议 | 下拉+文本 |
| 未解决问题 | 问题描述/滞留原因/处理思路 | 动态表格 |
| 下周计划 | 计划条目+总部支持需求 | 多行文本 |

**去重规则**：同学校+同工程师+同周报周期只保留一份，重复弹窗确认覆盖。

## 四、产品案例

### 4.1 页面布局

以模块为维度，聚合所有学校的该模块使用数据。数据完全来自用户画像查询（不新增存储表）。

```
┌──────────────────────────────────────────────────────────────┐
│  产品案例                                                     │
│  筛选：[科室▼] [模块▼] [学校类型▼]                              │
├──────────────────────────────────────────────────────────────┤
│  ◆ 统计概览：落地学校 / 平均使用率 / 活跃用户 / 素材总数         │
│  ◆ 学校分布地图：中国地图打点                                   │
│  ◆ 学校使用率排行：横向柱状图                                  │
│  ◆ 学校类型分布：环形图                                        │
│  ◆ 落地学校列表：表格+勾选对比                                 │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 产品模块使用排名

按产品/模块维度展示跨校落地情况：

| 产品/模块 | 落地学校数 | 🟢正式 | 🔵试用 | 🟡已购 | 🟠未购 | 覆盖率 | 排名 |
- TOP3 行底色微绿（核心产品），BOTTOM 3 行底色微红（薄弱产品）
- 每行展开「排名提示词」：为何排在此位置、推广建议/原因对对策
- 覆盖率 = 落地学校数 / 所有学校数 × 100%

### 4.3 省份画像分布（矩形树图）

矩形面积与画像数量成正比，颜色深浅表示数量多少。悬停显示：省份名、画像数量、占比、学校类型分布。点击省份下钻学校列表。

## 五、学校类型适配

不同学校类型自动调整科室列表和模块推荐：

| 类型 | 缺失/弱化的科室 | 额外/强化的科室 |
|------|----------------|----------------|
| 幼儿园 | 宿管/招生办/就业处/督导室 | 家校共育（强） |
| 小学 | 宿管/招生办/就业处/督导室 | 家校共育、心理中心 |
| 初中 | 招生办/就业处/督导室 | +宿管科、德育处 |
| 高中 | 招生办/就业处 | +考务（强）、成绩分析（强）、督导室 |
| 中职 | —（全科室） | +招生办（强）、就业处/实习办（强）、实训室（强） |
| 高职 | —（全科室） | +科研（强）、就业处、教研室 |
| K12 | 招生办/就业处/督导室 | 小学+初中合并 |

- 不存在的科室不展示，不适用模块不推荐
- 学校类型不可修改（类型变更=重新建档）

## 六、产品素材管理

仅 🟢正式使用 和 🔵试用中 的模块可上传，每模块最多 3 个文件：

| 类型 | 格式 | 大小限制 |
|------|------|----------|
| 视频 | mp4/mov/avi | ≤500MB |
| PPT | ppt/pptx | ≤100MB |
| 文字 | md/txt | ≤10MB |

**清理规则**：模块降级（→🟡已购未用/🟠未购）时自动删除 OSS 文件+DB 记录，弹窗确认。

## 七、版本历史

每次编辑或周报提交后生成一条版本记录：

```
id | profile_id | version_num | changed_fields(JSON) | diff_summary | operator | created_at
```

- 时间轴查看 v1→vN 全链路演变
- 等级变化节点追踪
- 模块增长曲线（通过版本 diff 绘制）
- 点击版本展开变更前后对比

## 八、AI 报告生成（Dock 栏新增）

Dock 栏新增「AI」按钮，替代原「周报」入口。点击后弹出选择框：

1. **选择是否包含项目数据 + 画像数据**
2. **默认包含科室数据**
3. **生成选项**：
   - 生成 AI 科室报告（逐科室分析）
   - 生成 AI 总览报告（全校汇总分析）

使用全局配置的大模型 Key，基于画像数据和项目数据分析生成报告。

## 九、数据库设计

案例中心使用**独立 Schema `design_case_center`**。

### 9.1 design_customer（主表）

| 类别 | 示例字段 | 类型 |
|------|---------|------|
| 基础 | school_name, school_types(多选数组), campus_mode, campuses(JSON) | VARCHAR/INT/JSON |
| 位置 | province, city, district, town, village, longitude, latitude | VARCHAR/TEXT |
| 硬件 | hardware_*_count, server_list, virtualization, wireless_coverage, bastion_host | VARCHAR/INT/TEXT |
| 科室业务 | dept_*_name(可修改), role, work, flow, pain, tools, expect, dept_scope, campus_id | VARCHAR/TEXT |
| 科室数据 | dept_*_metrics | JSON |
| 模块状态 | dept_*_module_*_status, usage_rate, active_users, effect, issue, collaborator_depts(JSON) | VARCHAR/INT/TEXT |
| 模块素材 | dept_*_module_*_files | JSON |
| 周报 | weekly_reports | JSON 数组 |
| 等级 | info_level | VARCHAR |
| 溯源 | source | VARCHAR |

### 9.2 profile_versions

```
id | profile_id(FK) | version_num | changed_fields(JSON) | diff_summary | operator | created_at
```

### 9.3 规则

- 空值默认：「未采集」/ false / 0
- 等级：初级 <20% / 中级 20-50% / 高级 >50%
- 溯源标注：所有字段标注来源（项目初始数据 / 调研表 / 周报）

## 十、核心交互流

```

  ↓

  ↓ 点击学校               ↓ 新建/导入
```

### 11.7 通用规则

- 风格：BI 数据看板风格，信息密度高，一眼抓住重点
- 不同业务板块有不同颜色/装饰，但不过于花哨
- 选择框无论选中与否宽度固定
- 所有多行文本输入有固定高度
- 模块卡片：4px 左边框色带区分状态
- 进度条：6-8px 高度，圆角填充，颜色对应阈值
- 数字大字体 + 小号标签区分视觉权重

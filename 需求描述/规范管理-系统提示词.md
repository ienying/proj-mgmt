# 规范管理 — 系统提示词

> 本文档根据现有代码实现反向梳理，可作为在其他项目中复刻该功能的提示词。

---

# 角色
你是一个全栈开发专家，精通 Next.js + React + TypeScript + PostgreSQL 技术栈，同时具备动态数据表管理系统的架构设计能力。

# 任务
实现「规范管理」模块——一个动态数据表定义与管理工具，允许管理员创建、配置和管理标准化数据表模板（规范表），这些模板在项目创建时自动复制到项目 Schema 中。

---

## 一、模块定位

规范管理是系统的**数据表模板管理中心**，在 Dock 导航栏显示为独立的导航项。

核心职责：
1. **定义数据表结构**：创建表、定义列（字段）、配置列属性
2. **管理规范数据**：在规范表中维护标准化数据，作为项目表的初始数据
3. **快捷输入配置**：为文本列配置快捷语，提升数据录入效率
4. **AI 辅助录入**：通过 AI 读取文件并生成数据预览，确认后批量导入

## 二、数据表管理

### 2.1 表列表

- 展示所有已创建的规范表
- 每行显示：表名称、表代码、列数、数据行数、创建时间、操作按钮
- 支持搜索和筛选
- 操作：查看数据 / 编辑结构 / 复制表 / 删除表

### 2.2 创建表

填写基本信息：

| 字段 | 必填 | 说明 |
|------|:--:|------|
| 表名称 | * | 中文显示名称 |
| 表代码 | * | 英文标识（小写+下划线） |
| 所属模块 | * | 10 大管理模块之一 |
| 描述 | | 表的用途说明 |

创建后进入列配置页面。

### 2.3 列配置

每张表可配置多个列（字段），每个列支持以下属性：

| 属性 | 说明 | 可选值 |
|------|------|--------|
| 列名 | 中文显示名 | 文本 |
| 列代码 | 英文标识 | 文本（小写+下划线，创建后不可修改） |
| 列类型 | 数据类型 | 见下方列类型详解 |
| 必填 | 是否必填 | 布尔 |
| 排序号 | 显示排序 | 数字 |
| 选项值 | 下拉/多选的选项 | JSON 数组 `[{label, value, color?}]` |
| 只读 | 数据是否只读 | 布尔 |
| 只读模式 | 只读逻辑 | AND / OR |
| 只读条件 | 触发只读的条件 | 依赖于其他列的特定值 `[{columnCode, operator, value}]` |
| 快捷语 | 文本列的快速填充短语 | 字符串数组（仅 text 类型） |
| 文件类型限制 | 允许上传的文件类型 | MIME 类型数组（仅 file 类型） |
| 文件大小限制 | 单个文件最大 | MB（仅 file/video 类型） |
| 视频时长限制 | 单个视频最长 | 秒（仅 video 类型） |

#### 列类型详解

| 类型 | 标识 | 数据库类型 | 前端编辑控件 | 说明 |
|------|------|-----------|------------|------|
| **text** | 文本 | `TEXT` | `<Input>` / `<Textarea>` | 单行或多行文本，支持快捷语 |
| **number** | 数字 | `DECIMAL(18,2)` | `<Input type="number">` | 数值，可配置小数位数 |
| **date** | 日期 | `DATE` | `<input type="date">` | 日期选择 |
| **select_single** | 单选下拉 | `TEXT` | `<Select>` / `<RadioGroup>` | 从预设选项中选择一个 |
| **select_multi** | 多选 | `TEXT[]` | `<Checkbox>` 组 | 从预设选项中选择多个 |
| **file** | 文件上传 | `JSONB` | `<FileUploadField>` | 附件上传，存储 `[{name, url, size, type}]` |
| **video** | 视频上传 | `JSONB` | `<VideoUploadField>` | 视频上传，存储 `[{name, url, size, duration}]` |
| **readonly** | 只读 | `TEXT` | 灰色文字 | 不可编辑的展示列 |
| **procurement_record** | 采购模块 | `TEXT` | Portal 搜索弹窗 | 自动生成采购模块记录行 |
| **ai_input** | AI 输入 | `TEXT` | AI 文件解析 | 上传文件 → AI 解析 → 预览确认后批量填入 |

**只读条件运算符**：

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `=` | 等于 | `status = "已完成"` |
| `!=` | 不等于 | `status != "已关闭"` |
| `IN` | 在列表中 | `status IN ["已完成", "已关闭"]` |
| `NOT_IN` | 不在列表中 | `dept NOT_IN ["技术部"]` |
| `IS_NULL` | 为空 | `inspector IS NULL` |
| `IS_NOT_NULL` | 不为空 | `approver IS NOT NULL` |
| `>` / `<` / `>=` / `<=` | 比较 | `progress >= 80` |

**AND/OR 模式示例**：

```
AND 模式 (全部条件同时满足 → 只读):
  条件A: status = "已验收"
  条件B: amount > 0
  → 当状态="已验收" 且 金额>0 时，该列只读

OR 模式 (任一条件满足 → 只读):
  条件A: status = "已关闭"
  条件B: approver = "张三"
  → 当状态="已关闭" 或 审批人="张三" 时，该列只读
```

### 2.4 AI 输入列类型

列类型 `ai_input` 允许用户通过上传文件 + AI 解析的方式批量填入数据。

**完整交互流程**：

```
点击 AI 输入单元格
  → 弹出 AI 数据录入弹窗
  → 上传文件 (Excel .xlsx/.xls / CSV / Word .docx)
  → 前端将文件发送到 POST /api/ai/parse-file
  → 后端:
      1. 解析文件内容 (Excel: exceljs / CSV: 逐行解析 / Word: 提取表格)
      2. 将解析的结构化数据发送给 DeepSeek
      3. Prompt: "以下是从文件中解析的数据，请根据目标表的列定义映射数据到对应列"
      4. 返回映射后的数据 [{col1: val1, col2: val2, ...}]
  → 前端展示预览表:
      ┌─ AI 数据预览 ──────────────────────────────┐
      │ 已解析: 156 行 × 8 列                        │
      │ 匹配目标列: 模块名称 / 负责人 / 日期 / 状态   │
      │ ┌───────────────────────────────────────┐   │
      │ │ 模块名称 │ 负责人 │ 日期     │ 状态    │   │
      │ │ 课表中心 │ 张三   │ 2026-01  │ 进行中  │   │
      │ │ 考务管理 │ 李四   │ 2026-02  │ 已完成  │   │
      │ │ ...                                  │   │
      │ └───────────────────────────────────────┘   │
      │ 共 156 行，其中 12 行数据不完整(黄色标记)      │
      │ [取消] [仅导入完整行] [全部导入]               │
      └──────────────────────────────────────────────┘
  → 用户确认后:
      - 逐行 INSERT 到目标表
      - data_source = 'manual', allow_delete = true
      - 冲突行（重复主键等）跳过 + 汇总报告
```

**后端解析逻辑**：

| 文件类型 | 解析方式 | 提取内容 |
|----------|----------|----------|
| `.xlsx/.xls` | exceljs 逐 sheet 解析 | 表头行 + 数据行 |
| `.csv` | 逐行解析 + 自动检测分隔符 | 首行作表头 + 数据行 |
| `.docx` | mammoth 提取 + 表格检测 | 文档中嵌入的表格 |

**AI 映射逻辑**：
- 将解析的文件列名与目标表的列名进行语义匹配
- 模糊匹配：列名相似度 > 80% → 自动映射
- 精确匹配：列名完全一致 → 直接映射
- 未匹配列：在预览表中灰色显示，提供手动映射下拉
- 预览表中黄色标记数据不完整或格式不匹配的行

**错误处理**：
- 文件格式不支持 → toast "不支持的文件格式，请上传 Excel/CSV/Word"
- 文件过大（> 10MB）→ toast "文件过大"
- AI 解析失败 → 显示原始错误 + 重试按钮
- 无匹配列 → "AI 无法识别文件中的列与目标表的对应关系，请手动映射"

### 2.5 快捷语配置

当列类型为 `text` 时，列配置中增加「快捷语」子行：

- **配置阶段**：在规范管理中编辑列配置时，添加绿色的「快捷语」子行
- 输入快捷语后按回车添加，点击 ✕ 移除
- 导出/导入 Excel 时包含「快捷语」列
- **使用阶段**：在项目详情或规范管理中填写文本字段时，输入框上方以绿色标签形式显示已配置的快捷语，点击即可填入

### 2.6 卡片式列配置布局

列配置采用卡片式布局，每列独立显示一张配置卡片：
- 卡片内显示该列的所有配置属性
- 视觉上清晰区分不同列
- 支持拖拽排序列顺序

## 三、数据管理

### 3.1 规范数据表

每张规范表对应一个 PostgreSQL 物理表（`design_public.std_definition_{table_code}`），同时维护一份公共数据（初始种子数据）。

### 3.2 数据操作

- 表格视图展示所有数据行
- 支持行内编辑、新增行、删除行
- 文本列显示快捷语标签，点击填入
- 支持 Excel 导入/导出

### 3.3 导出/导入

- 导出：CSV/Excel 格式，BOM UTF-8 编码，包含所有列（含快捷语列）
- 导入：解析 Excel 文件，预览后确认导入

## 四、项目创建时的表复制

规范管理定义的规范表是项目数据表的模板。项目创建时，规范表按匹配规则自动复制到项目 Schema。

### 4.1 匹配规则体系

匹配规则在系统设置 → Schema 自动匹配规则中配置。七级优先级：

```
优先级 1 (最高): 类型+阶段精确匹配
  project_type = "新建" AND project_stage = "建设阶段"
  → 复制: scope_reg, progress_track, quality_check, ...

优先级 2: 仅类型匹配
  project_type = "新建" (project_stage IS NULL)
  → 复制: requirement_reg, ...

优先级 3: 仅阶段匹配
  project_stage = "运维阶段" (project_type IS NULL)
  → 复制: maintenance_log, ...

优先级 4: 通用规则 (兜底)
  project_type IS NULL AND project_stage IS NULL
  → 复制: communication_log, risk_reg, ...

优先级 5: 模块规则 (按采购模块交集)
  项目的采购模块 ∩ 规则的 module_codes ≠ ∅
  → 复制: procurement_record, ...

优先级 6: 直接匹配
  项目的类型 IN apply_project_types 或 阶段 IN apply_project_stages
  → 复制: 对应表的规范数据

优先级 7 (最低): 模块配置匹配
  通过 project_type_stage_modules 二维矩阵
  → 根据启用的模块决定复制哪些表
```

### 4.2 复制流程

1. 遍历七级规则，收集所有匹配的规范表 code（去重）
2. 在项目 Schema (`yuansu_{project_code}`) 中逐一 `CREATE TABLE IF NOT EXISTS`
3. 表结构 = 规范表列定义 + 系统字段（id/sort_order/created_at/updated_at/created_by/allow_delete/data_source/_module_code）
4. 从 `design_public.std_definition_{table_code}` 复制初始数据行
5. 复制数据的 `data_source` 设为 `standard`，`allow_delete` 设为 `false`
6. 为包含 `procurement_record` 列类型的表，按项目选择的采购模块逐条生成记录行

### 4.3 编辑项目时的变更处理

- 项目类型/阶段变更 → 重新匹配 → 新增匹配的表 `CREATE TABLE IF NOT EXISTS`
- `IF NOT EXISTS` 保证已有表不会被删除或重建
- 不再匹配的模块 Tab 隐藏，但数据保留在 Schema 中

### 4.4 列定义同步

规范表的列定义变更（新增/删除/修改列）不会自动同步到已有项目。需要管理员手动触发：
- 「同步到已有项目」按钮：选择规范表 → 选择目标项目 → 逐项目执行 `ALTER TABLE ADD COLUMN IF NOT EXISTS`
- 删除列：仅隐藏（不在前端显示），不执行 `DROP COLUMN`（数据安全）

### 7.6 通用规则

- 拖拽排序使用 `@dnd-kit` 库
- 删除操作需 confirm 确认
- 数据操作有 toast 反馈 (sonner)
- 导出 Excel 使用 exceljs 库，BOM UTF-8 编码

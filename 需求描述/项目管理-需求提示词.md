# 项目管理 — 需求提示词

> 本文档根据现有代码实现反向梳理，可作为在其他项目中复刻该功能的提示词。

---

# 角色
你是一个全栈开发专家，精通 Next.js + React + TypeScript + PostgreSQL 技术栈，同时具备企业级项目管理系统的架构设计能力。

# 任务
实现一个名为「项目管理」的完整项目生命周期管理模块。

---

## 一、模块定位

项目管理模块是整个平台的中枢，负责管理项目的全生命周期：

1. **项目创建**：填写项目基本信息、客户信息、渠道信息、采购模块，自动生成隔离的项目数据 Schema
2. **项目列表**：多维筛选、阶段侧边导航、列表/卡片双视图切换、CSV 导出
3. **项目详情**：10 大管理模块（对标 PMBOK 知识领域），每个模块下挂载多个数据表，支持多种视图
4. **成员与权限**：精细粒度的项目级权限控制（8 项权限）

该模块在主导航栏 Dock 中显示为「项目管理」（蓝色 FolderKanban 图标）。

### 3.3 提交逻辑

1. 前段校验必填项（名称/编号/类型/阶段/至少一个采购模块）
2. 项目编号唯一性校验（小写英文+数字+下划线格式）
3. 项目编号重复时 toast 提示"项目编号已存在"
4. 创建成功后自动：
   - 生成项目 Schema（命名规则：`yuansu_{project_code}`）
   - 按规则匹配并复制规范表到项目 Schema
   - 为含 `procurement_record` 类型列的表自动生成采购模块记录行
   - 插入项目成员记录
5. 编辑模式下，若项目类型或阶段变更，弹出确认对话框提示影响：
   - 模块 Tab 将根据新配置刷新
   - 匹配新类型/阶段的规范表将自动创建到项目 Schema
   - 已有数据不会被删除
   - 不再启用的模块 Tab 隐藏但数据保留

### 4.3 数据表展示

每个模块下挂载若干数据表（来自规范表定义），每张表独立展示为一张卡片：

- **表头**：渐变色背景 + 白色文字（表中文名 + 行数统计）
- **工具栏**：视图模式切换 + 新增按钮（可选）

### 4.4 9 种数据视图模式

所有视图配置持久化到 localStorage（按表 Code 分组存储，key: `view_config_{tableCode}`）。每种视图有独立配置面板，点击视图按钮旁的 ⚙ 图标打开。

#### a. 表格视图（table）

最常用的数据展示模式，以行列二维表格呈现。

**配置项**：
| 配置 | 说明 | 默认值 |
|------|------|--------|
| 冻结列数 | 左侧固定不滚动的列数 | 0 |
| 冻结行数 | 表头下方固定的行数 | 0（仅表头 sticky） |
| 显示列 | 选择哪些列可见 | 全部 |
| 列宽 | 每列的像素宽度 | 自动均分 |

**列宽拖拽**：表头每列右侧有 4px 拖拽手柄，hover 变蓝，拖拽后宽度持久化到 localStorage。

**可编辑列判定**：单元格是否可编辑由三个条件决定：
1. 行数据来源（`data_source`）= `manual` → 允许编辑；`standard` / `procurement_module` → 禁止编辑
2. 列配置 `is_readonly` = true → 禁止编辑
3. 列配置 `readonly_conditions` 满足 → 禁止编辑（见下文只读控制）

**单元格编辑态控件映射**：
| 列类型 | 编辑控件 | 说明 |
|--------|----------|------|
| text | `<Input>` 内联 | 单行文本，focus 自动全选 |
| number | `<Input type="number">` | 数字输入 |
| date | `<input type="date">` | 日期选择 |
| select_single | `<Select>` 或 `<RadioGroup>` | 下拉或单选组 |
| select_multi | `<Checkbox>` 组 | 多选复选框 |
| procurement_record | Portal 弹出搜索弹窗 | 带搜索的采购模块选择器，支持单选/多选 |
| file | `<FileUploadField>` | office/pdf/md/image/archive，多文件 |
| video | `<VideoUploadField>` | mp4/mov/avi，大小限制 |
| readonly | 灰色文字 | 不可编辑，显示 "(只读)" |
| ai_input | AI 分析按钮 | 上传文件 → AI 解析 → 预览确认 |

**编辑态快捷键**：Enter → 确认保存 / Escape → 取消编辑 / Tab → 确认并移到下一格

**行删除**：仅 `data_source = 'manual'` 的行显示删除按钮。标准数据行（`standard`）和采购模块行（`procurement_module`）不可删除。

#### b. 卡片视图（card）

每行数据渲染为一张独立卡片，网格布局。

**配置项**：
| 配置 | 说明 |
|------|------|
| 显示字段 | Popover 勾选要在卡片上展示的字段（默认全部） |
| 每行列数 | 1/2/3/4 列 |
| 标题字段 | 选择作为卡片标题的字段 |

卡片内字段布局：
```
┌──────────────────────┐
│ 标题字段值 (粗体)      │
│ ─────────────────── │
│ 字段A: 值            │
│ 字段B: 值            │
│ 字段C: 值            │
│ ...                  │
└──────────────────────┘
```

#### c. 看板视图（kanban）

按指定字段值将数据分列展示，类似 Trello 看板。使用 `@dnd-kit` 实现卡片拖拽。

**配置项**：
| 配置 | 说明 |
|------|------|
| 看板字段 | 单选/下拉类型字段（如"状态"） |
| 显示字段 | 卡片上显示的字段 |
| 排序字段 | 列内排序依据 |

**交互**：
- 列头显示字段值 + 该列卡片数
- 卡片拖拽到其他列 → 自动更新该行看板字段的值 → API 同步
- 空列显示 "拖拽卡片到此处"
- 列内卡片垂直排列，列间横向滚动
- 卡片支持内联编辑（点击字段直接修改）

#### d. 树形视图（tree）

数据按多级字段分组，形成树形层级结构。

**配置项**：
| 配置 | 说明 |
|------|------|
| 第1级分组字段 | 必填 |
| 第2级分组字段 | 可选 |
| 第3级分组字段 | 可选 |
| 第4级分组字段 | 可选 |

**展示逻辑**：
- 按照配置的分组字段形成 1-4 级树节点
- 未设级别的字段在最后一级横向展示（表格形式）
- 点击节点展开/折叠子节点
- 每级缩进 20px，连线连接父子
- 每个节点显示：字段值 + 该组行数 badge

#### e. 表单视图（form）

单条记录浏览模式，左右箭头翻页。

**交互**：
- 左侧显示字段标签，右侧显示字段值
- 只读字段灰底显示
- 可编辑字段支持直接修改 → 保存
- 底部：「← 上一条」「下一条 →」+ 页码（第 X/Y 条）
- 支持键盘 ← → 翻页

#### f. 甘特图视图（gantt）

项目时间线可视化，自研实现（不依赖第三方甘特图库）。

**配置项**：
| 配置 | 说明 |
|------|------|
| 任务名称字段 | 左侧显示的任务标题 |
| 计划开始日期字段 | 蓝色条起点 |
| 计划结束日期字段 | 蓝色条终点 |
| 实际开始日期字段 | 绿色条起点（可选） |
| 实际结束日期字段 | 绿色条终点（可选） |
| 分组字段 | 左侧分组（可选） |
| 进度字段 | 进度百分比（可选） |

**显示规则**：
- 蓝色条 = 计划时间线（从计划开始到计划结束）
- 绿色条 = 实际时间线（在实际条下方/上方）
- 红色标记 = 延期部分（实际结束 > 计划结束）
- 橙色标记 = 进度落后（当前日期 > 计划进度对应的日期）
- 竖虚线 = 今日线
- 时间刻度：日/周/月三档切换

#### g. 分组视图（group）

支持多级分组字段的数据聚合视图。

**配置项**：
| 配置 | 说明 |
|------|------|
| 分组字段 | 动态添加/删除/拖拽排序（如：部门 → 状态 → 负责人） |
| 显示字段 | 分组内每行显示的字段 |
| 聚合方式 | count / sum / avg（数字字段） |

**交互**：
- 分组头显示：字段名 + 字段值 + 行数 + 聚合值
- 点击分组头展开/折叠
- 列宽可拖拽调整
- 展开后显示该组下所有数据行

#### h. 色标脉络视图（trace）

用于可视化数据流转关系。配置项包含：分组字段（必填）、分支字段（必填）、主行字段（最多 3 个）、串联字段（多个，可排序）。

**显示逻辑**：
- 按分组字段将记录分组
- 组内按分支字段形成并行线（分支字段值相同 → 同一行；不同 → 新行）
- 每行按串联字段顺序形成节点流（从左到右排列）
- 每个串联列有独立色标（从 12 色调色板循环：红/橙/黄/绿/青/蓝/紫/粉/棕/灰/indigo/teal）
- 节点内显示对应的字段值

#### i. 进度条视图（progress）

复用色标脉络配置结构，每个节点以进度条形式展示（高度 12px，圆角 6px），适用于展示各阶段完成百分比。

### 4.5 内联编辑

- 点击单元格进入编辑态
- 根据列类型渲染不同的编辑控件（Input/Select/Checkbox/RadioGroup/FileUpload/VideoUpload）
- 保存后立即 `PUT /api/project-data` 更新
- 只读列不可编辑

### 4.6 新增记录

- 弹出新增对话框，动态渲染所有字段的表单
- 支持引用选择器：从其他表选取记录并自动填充到当前行的对应列

### 4.7 引用关系

数据表间可配置双向引用关系，实现跨表数据联动。

**配置存储**：每张表可选配置 `references_config` JSON 字段：

```json
[
  {
    "sourceTableCode": "scope_reg",
    "sourceColumnCode": "module_name",
    "targetTableCode": "progress_track",
    "targetColumnCode": "ref_module",
    "syncDirection": "bidirectional"
  }
]
```

**引用生效规则**：
- 引用列（targetColumnCode）在目标表中以**只读**方式展示
- 值自动从源表的对应列（sourceColumnCode）中匹配获取
- 匹配依据：源表和目标表中具有相同值的主键字段（通常是项目内统一的标识字段）
- 手动编辑引用列 → 自动同步到源表对应列

**自动同步 API**：`POST /api/project-data/sync-references`
- 接收参数：`projectSchema`, `tableCode`, `rowId`
- 遍历该表的所有 `references_config`，执行双向同步
- 在编辑保存、删除行时自动调用

**前端交互**：
- 引用列显示为浅蓝色背景 + 🔗 图标（区别于普通只读列）
- hover 显示 Tooltip："引用自 {源表名}.{源列名}"
- 点击引用单元格 → 跳转到源表对应行（可选功能）

### 4.8 关联流程任务

项目数据行可与任务中心的流程任务关联，实现"一条数据 → 一个审批流程"的绑定。

**关联方式**：
- 在数据行操作菜单中点击「关联任务」
- 弹出任务选择器：列出任务中心中所有 `source_type = 'project_data'` 的任务定义
- 选择后，该行数据的 `linked_task_id` 字段记录任务实例 ID

**显示规则**：
- 行内显示关联的任务定义名称（蓝色可点击标签）
- 点击标签 → 跳转到任务中心该任务详情
- 已关联任务的行背景色微蓝（#eff6ff），hover 显示"已关联流程: XXX"

**解除关联**：
- 在数据行操作菜单中点击「解除关联」
- 弹出确认对话框
- 解除后任务本身不受影响（仅解除绑定关系）

### 4.9 数据行列只读控制（AND/OR 模式）

列配置中设置只读条件和模式：

**AND 模式**：所有条件同时满足时，该列才变为只读
```
例：列 "验收日期" 设置条件
  - 条件A: 状态 ≠ "已完成"
  - 条件B: 验收人 IS NULL
  → AND 模式：两个条件都满足时，"验收日期" 列只读
```

**OR 模式**：任一条件满足时，该列即变为只读
```
例：列 "备注" 设置条件
  - 条件A: 状态 = "已关闭"
  - 条件B: 审批人 = "张三"
  → OR 模式：状态为"已关闭" 或 审批人为"张三" 时，"备注" 列只读
```

**配置存储**：
```json
{
  "readonly_mode": "AND",
  "readonly_conditions": [
    { "columnCode": "status", "operator": "!=", "value": "已完成" },
    { "columnCode": "inspector", "operator": "IS_NULL", "value": "" }
  ]
}
```

**前端渲染**：
- 满足只读条件的单元格 → 灰色背景(#f1f5f9) + 文字 "(只读)" + 禁止点击
- 行内部分列只读、部分列可编辑（全链路正确判定）

## 六、数据 Schema 隔离

### 6.1 核心设计

每个项目创建独立的 PostgreSQL Schema（`yuansu_{project_code}`），实现项目间数据完全隔离。

### 6.2 Schema 生成逻辑

项目创建时自动执行以下完整流程：

#### 第 1 步：创建 Schema
```sql
CREATE SCHEMA IF NOT EXISTS yuansu_{project_code};
```

#### 第 2 步：按规则匹配规范表

按七级优先级依次匹配（由高到低）：

| 优先级 | 规则类型 | 匹配条件 |
|--------|----------|----------|
| 1 | 类型+阶段精确匹配 | `project_type` + `project_stage` 都相等 |
| 2 | 类型匹配 | 仅 `project_type` 相等（`project_stage` = null） |
| 3 | 阶段匹配 | 仅 `project_stage` 相等（`project_type` = null） |
| 4 | 通用规则 | `project_type` = null 且 `project_stage` = null |
| 5 | 模块规则 | `module_codes` 与项目采购模块有交集 |
| 6 | 直接匹配 | `apply_project_types` / `apply_project_stages` 包含当前值 |
| 7 | 模块配置匹配 | `project_type_stage_modules` 中启用的模块 |

同一规则类型匹配多张表时，全部复制。

#### 第 3 步：创建表结构

在项目 Schema 中逐一执行：
```sql
CREATE TABLE IF NOT EXISTS yuansu_{project_code}.{table_code} (
  -- 自定义列（从规范表 column_definitions 读取）
  {column_code} {column_type} {constraints},
  ...
  -- 系统字段（自动追加）
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  sort_order INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  created_by VARCHAR(36),
  allow_delete BOOLEAN DEFAULT true,
  data_source TEXT DEFAULT 'manual',
  _module_code VARCHAR(255)
);
```

`IF NOT EXISTS` 保证编辑项目时只增不删——已有表不会被重复创建，新匹配的表会被追加。

#### 第 4 步：复制规范数据

从 `design_public.std_definition_{table_code}` 复制规范数据（`data_source = 'standard'`）到项目 Schema，同时将初始数据的 `allow_delete` 设为 `false`。

#### 第 5 步：生成采购模块记录行

对含 `procurement_record` 类型列的表，按项目选择的采购模块自动插入记录行：
- 每个采购模块生成一行，`_module_code` = 模块 code
- 如果表中有列代码与采购模块 code 匹配的列，默认填入该模块名称
- `data_source` = `procurement_module`，`allow_delete` = `false`
- 按模块排序号升序排列

#### 第 6 步：插入项目成员记录

从创建表单的成员信息插入 `project_members` 表。

#### 编辑项目时的特殊处理

- Schema 生成规则同上（`IF NOT EXISTS` 保证只增不删）
- 若项目类型或阶段变更 → 弹出确认对话框：
  - "模块 Tab 将根据新配置刷新"
  - "匹配新类型/阶段的规范表将自动创建到项目 Schema"
  - "已有数据不会被删除"
  - "不再启用的模块 Tab 隐藏但数据保留"

### 6.3 统一表结构

每个动态表额外包含系统字段：

| 系统字段 | 类型 | 说明 |
|----------|------|------|
| id | UUID PK | gen_random_uuid() |
| sort_order | INTEGER | 排序号，默认 0 |
| created_at | TIMESTAMPTZ | 创建时间 |
| updated_at | TIMESTAMPTZ | 更新时间 |
| created_by | VARCHAR(36) | 创建人 |
| allow_delete | BOOLEAN | 是否允许删除，默认 true |
| data_source | TEXT | 数据来源：standard / manual / procurement_module |
| _module_code | VARCHAR(255) | 采购模块隐藏列（仅 procurement_record 表） |

### 9.6 通用规则

- 整体风格：白底圆角卡片 + 浅灰背景
- 10 大模块各有独立渐变色头部
- 状态标签 4 种样式（蓝/绿/琥珀/红）
- 创建表单 8 种 Section 主题色，输入框聚焦环色匹配
- 视图切换按钮组：浅灰底 + 选中白底阴影
- 所有视图配置持久化到 localStorage
- 删除操作需 confirm 确认
- 数据操作 toast 反馈 (sonner)
